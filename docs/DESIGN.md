# DESIGN.md — The Design System in Code

The taste contract for Aalishaan Studio: how the approved prototype's design becomes code.
`docs/TECH-ARCHITECTURE.md` fixes the *mechanics*; this file fixes the *taste*. The approved "design system" for
this project is not a separate document — it is the frozen prototype at `prototype/` (local revision E10 = public
E8 [R13 + M1–M5 + E8 logo] + the final Admin, "Admin A2 — 86400 UI edition" — D-PRE-23, D-36), so every value
below is transcribed from the prototype's stylesheets with its source cited. Implementation never re-decides a
visual question; when this file and the prototype disagree, the prototype is checked first and the discrepancy
is reported (see §1).

Source order for tokens: the inline `<style>` block in `prototype/index.html` ("AALISHAAN STUDIO — HOME v1.1",
lines 15–495) and its identical copy `prototype/shared/browse-home.css` (asset paths rewritten to `../`) define
the tokens. Later stylesheets override them; the per-page cascade order is load-bearing:
`browse-home` → `home-r2` → `browse` → [`pending` → `about-hub` → `storefront-r7`] → [`product/r3`] →
`gallery-r8` → `revision-r9` → `revision-r11`. §2 records the token default **and** the effective value after
overrides; the build reproduces the effective value.

Source order for the Admin: `prototype/admin/index.html:2` loads three stylesheets in this order —
`admin.css` (retained A1 base, unchanged) → `workspace.css` (retained A2 layer, unchanged) → `studio-ui.css`
(the **86400 design layer**: "Presentation only. Loaded last; … System fonts only. No remote assets or
packages.", `prototype/admin/studio-ui.css:1–3`). `studio-ui.css` redefines every `:root` token
(`studio-ui.css:4–18`) and is the design authority, **but it is only last, not most specific**: a handful of
more specific rules in the two retained files still win (focus-ring colour, active segmented tab, global-search
width, toast border — each recorded where it applies below). As on the storefront, the build reproduces the
**effective (rendered)** value. `prototype/admin/studio-ui.js` (loaded last of 16 scripts,
`prototype/admin/index.html:7`) is a presentation-only script — allowlisted copy simplification, labelled phone
record cards, the missing-image placeholder and drawer focus restoration (`studio-ui.js:1–4`); UI labels in the
docs are quoted as they render **after** it runs.

## 1. Binding rules (read first)

- [ ] **Mockups + approved copy are the source of truth.** The mockups are the prototype pages themselves (`prototype/index.html`, `prototype/shop-all/`, `prototype/product/`, `prototype/pages/**`, `prototype/admin/`) — D-PRE-00, D-PRE-02, D-PRE-23 in `docs/PROJECT-STATUS.md` §7 (the Admin mockup is the final Admin, "Admin A2 — 86400 UI edition"; AF1 §3's menu layout is superseded by it, AF1's 26 capabilities and US01–US23 are not). Approved copy is the generated HTML plus its build sources (`docs/APPROVED-INPUTS.md` §2 row 6; handling per D-08). The developer never invents a colour, spacing value, radius, or layout — and never rewrites approved copy. New strings (server errors, integration states, empty states for real data) go to `docs/content/new-strings.md` in the prototype's voice and are flagged for owner approval; locked numbers come from `docs/content/locked-facts.md`.
- [ ] **Drift rule:** if a built page disagrees with the prototype, **flag it** in `docs/PROJECT-STATUS.md` §8 (Open decisions) — never silently pick one. Deviations already recorded and leaning: D-11 (help search banner removed), D-14 (Instrument Sans on every page), D-15 (one focus-ring colour). Anything else is a new row.
- [ ] **Code-wins tie-break:** where this file and the shipped tokens (the global stylesheet created in S1.3) disagree, the code wins — update this file in the same PR.
- [ ] Locked facts/numbers the site claims (22 artworks, three finishes, A2, launch prices per D-PRE-08) are implemented verbatim and never drift through copy edits.
- [ ] **The public design and the desktop layout are locked.** "Preserve desktop unchanged" (D-PRE-05); public design locked at R13 (D-PRE-02); E7/M5 mobile refinements and the E8 logo are the last approved changes (D-PRE-06, D-PRE-07). Only the owner's explicit approval marks a page signed off — a passing test or a green Preview is not a sign-off.
- [ ] **`prototype/` is read-only.** Port design, copy, data and imagery deliberately; never import its runtime CSS/JS files as-is, never edit them (`CLAUDE.md` → Project-specific rules).
- [ ] **The Admin's prototype-only mechanisms are replaced, not ported (D-32), and its demo chrome is not built (D-31).** This file specifies the *look* of the final Admin — tokens, components, shell. It never turns the "LOCAL PROTOTYPE" bar, the scenario indicator, the role preview, "Sign-out preview", the passphrase vault UI or the local backup/restore controls into something a sprint builds (§4 lists the chrome that is not built). No owner visual sign-off of the final Admin screens is recorded (OI-14) — Admin sprints reproduce the reference and flag it in their Preview evidence.

## 2. Tokens (one source of truth in code)

All tokens live in **one global stylesheet / theme file** — planned path `src/styles/globals.css`, created in
S1.3 ("tokens from `DESIGN.md` §2 in one global stylesheet", `docs/ROADMAP.md` → S1.3). Tailwind's theme reads
these CSS custom properties; components read tokens only — **never inline hex in markup**. Token names carry
over from the prototype (`--crimson`, `--ink`, `--line-soft`, …) so a diff against the prototype CSS stays
literal; role aliases (for example `--color-primary: var(--crimson)`) may be added on top but the prototype name
stays canonical. This naming convention is proposed here and confirmed by the S1.3 PR (code wins). A rebrand
must be a one-file change.

## 4. Locked shell chrome

Shells approved in the sitemap: **public + admin — exactly two.** Each shell has one locked navigation system.
Chrome is identical on every page **within that shell** and is never redesigned per page. A transparent header
that solidifies on scroll is a state of the public shell, not a fork. The W1 wireframe (`prototype/admin/wireframe/`)

(`prototype/admin/index.html:7`) and never links to it (D-PRE-23, D-27). Adding or changing a shell requires an
updated sitemap/mockup and explicit owner authorization, recorded as a decision in `docs/PROJECT-STATUS.md` §8.

## 5. Motion rules

- Register: restrained UI transitions plus **one** scroll-driven sequence (Home). Don't mix registers — coherence beats novelty. No new animation register may be introduced without an owner decision. The Admin has its own, smaller motion budget (the "Admin motion" bullet below); storefront easing, durations and hover travel are never applied inside the Admin shell.
- Locked parameters — one easing curve `--ease: cubic-bezier(.2,0,0,1)`; base duration `--dur: 200ms`; cards 250 ms; drawers 260 ms (backdrop 200 ms); Home FAQ panel 260 ms; header solidify 300 ms; image hover zoom 400–450 ms (`browse-home.css:40–41, 298–303, 321–322, 434–435`; `product/r3.css`). Travel: hover arrows `translateX(3px)`; button `:active translateY(1px)`; toast/notice rise `1.5rem`; `.route-card:hover translateY(-5px)` (Home only); hover scale `1.015` (stage) / `1.025` (wall tiles) — nothing larger. Storefront art/collection cards have **no** hover transform (`gallery-r8.css:12`).
- Header solidify on scroll: transparent → `rgba(255,255,255,.95)` + `blur(18px)` + 1 px hairline shadow at `scrollY > 24`, 300 ms (`index.html:835`; `browse-home.css:434–436`).
- Drawers: `translateX(±102%) → 0`, 260 ms `var(--ease)`; backdrop opacity 200 ms.
- **Home wall-to-materials handoff — desktop** (`data-handoff="on"`, D-PRE-05 "desktop unchanged"): scroll-driven, `.opening-sequence` 280svh with a sticky 100svh `.opening-stage`; progress `p` = scrolled fraction, travel = `smoothstep(t)` of `progressRange(p, .07, .82)`, rAF-throttled. The `.travelling-art` (same `.framed-art` DOM as the wall frame) moves from the wall frame's measured rect to the `.anatomy__art` slot via `translate3d` + scale; coordinated custom properties `--wall-cover` (p .005–.065), `--room-shift` −70 px × travel, `--copy-opacity` 1→0 (p .015–.2), `--room-opacity` 1→0 (p .32–.88), `--details-opacity` 0→1 (p .58–.88), `--labels-opacity` 0→1 (p .78–.97) with `--labels-shift` 12px→0 (p .66–.9), lift shadow `--lift-y 12·sin(πt)` px / `--lift-blur 22·sin(πt)` px. Hero becomes `inert` + `aria-hidden` at p ≥ .13; details until p ≤ .8. Enabled only after wall images decode, fonts are ready and `(min-width: 901px) and (min-height: 680px)` matches (`index.html:975–1140`; `browse-home.css:183–192`). Static layout (`data-handoff="off"`) is the default.
- **Home wall-to-materials handoff — mobile** (`data-handoff="mobile"`, M4 signed off D-PRE-05): sequence 200svh, sticky 100svh stage; the lift runs between 4 % and 72 % of the scroll duration with exact wall-origin to destination geometry, no artwork fade-in, a landing pause, then natural scrolling to `.mobile-materials`; `--copy-opacity` (.015–.2), `--room-opacity` (.12–.62), `--details-opacity` (.52–.72); landed artwork retained on reverse scroll. Enabled when width ≤ 900, `innerHeight ≥ 520` and hero copy height + 280 ≤ `innerHeight`; otherwise static. The three promises and six material items move below the landing on mobile and are restored on desktop (`index.html:989–1004, 1035–1098`; `home-r6.css:44–70`).
- Other recorded motion: image hover zoom (product stage/tiles); receipt feed 2.2 s linear on confirmation (the older 1.2 s `receipt-print` is neutralised — do not port it); Home FAQ height 260 ms with 90° icon rotate 200 ms; smooth anchor scrolling (`html:not(.no-smooth){scroll-behavior:smooth}`).
- **Admin motion (the final Admin) — deliberately minimal, two movements only:** (1) the drawer entrance, `dialog[open]{animation: studio-slide .18s ease-out}` — an 18 px horizontal slide with a fade from `.4` to `1` (`prototype/admin/studio-ui.css:251`, `:261`); (2) the phone sidebar, `transition: transform .18s ease` between `translateX(-100%)` and `0` (`studio-ui.css:303–304`; it out-cascades the retained `.2s` of `workspace.css:5` and `admin.css:8`). Everything else is instant: button hover is `filter:brightness(.95)` with `transform:none` and no transition (`studio-ui.css:81`); nav, row, tab and menu hovers are colour changes without a transition; there is **no `:active` rule, no hover lift, no card transform and no easing or duration token** in any of the three Admin stylesheets. The Admin uses `ease-out` / `ease` at .18 s — never the storefront `--ease` / `--dur`. Focus restoration after a drawer closes is instant (`focus({preventScroll:true})`, `prototype/admin/studio-ui.js:164`). The retained `a.card:hover{transform:translateY(-1px)}` (`admin.css:4`) belongs to superseded A1 card screens that the final Admin no longer renders — it is not reproduced.
- Every animation respects `prefers-reduced-motion`: CSS sets `animation-duration:.001ms`, `iteration-count:1`, `transition-duration:.001ms` and `scroll-behavior:auto` globally (`browse-home.css:399–402`) with `transition:none` in every later stylesheet (`browse.css`, `gallery-r8.css`, `storefront-r7.css`, `product/r3.css:236–238`, `revision-r9.css`); the Admin resets `animation:none!important; transition:none!important; scroll-behavior:auto!important` on `*, *:before, *:after` (`prototype/admin/studio-ui.css:410–412`, with equivalents retained in `workspace.css:6` and `admin.css:11`), so the drawer and the phone sidebar simply appear; JS gates the handoff on `!matchMedia('(prefers-reduced-motion: reduce)').matches` and falls back to the readable static layout (`index.html:981, 1040`), anchor scrolls use `behavior:'auto'`. The build reproduces both the CSS and JS guards.
- **Never do this:** no parallax, cursor effects, springs, or auto-playing motion anywhere else without explicit, dated owner sign-off recorded as a decision ID in `docs/PROJECT-STATUS.md` §8 — and exceptions can be RETIRED, recorded the same way. The Home handoff is the only scroll-driven sequence; no page other than Home gets one.

## 8. Frontend craft — professional finish

The bar for every page is "looks professionally designed", not "renders without errors". Tokens (§2), motion (§5), and accessibility (§6) already bind; this section adds the craft rules that stop a site looking templated.

- **Visual thesis** (derived from the prototype — not a quotation from any approved document): *a quiet gallery-white page where the artwork is the only rich colour, crimson appears only where the visitor can act, gold appears only as a small tracked mark, and every heading is a light-weight display face set with generous air.* Every page serves it; a choice that doesn't serve it is out. The **Admin** thesis, in the package's own words: "light grey canvas, white cards, restrained green accents, system typography, quiet borders, consistent controls and right-side drawers" (`prototype/admin/README.md`) — a calm working tool, with two precisions the CSS adds: primary actions are ink, not green, and the one serif is the "Aalishaan" word-mark.
- **Anti-generic rules (blocking):**
  - No framework-default look — no Tailwind default palette, ring, radius or shadow left in place; typography pairing (storefront: Charsen 400 + Instrument Sans; Admin: the system stack) and colour roles come from §2 only.
  - Consistent shape language: on the storefront 4 px radii, 1 px hairlines, no fills for structure, one stroke icon style — no per-component improvisation; the §2 exceptions list is closed. The Admin has its own closed register (15 px cards, 8 px controls, square drawer — §2 "Admin — radii").
  - Every interactive element has designed hover, focus-visible, and active states from §3 (storefront: secondary button border → ink; art-card border → `#b8afa2`; text-link arrow shift; button `:active` 1 px press; Admin: the hover / current states of its §3 rows and the `#88a894` ring — the Admin has no `:active` style) — not browser defaults.
  - Imagery meets the recorded bar: artwork contained on white, never cropped or stretched; rooms cover-fit; heroes masked as the prototype masks them; no stock imagery — every image is a prototype asset.
  - Real content rhythm at review — no lorem ipsum in a PR; section density varies deliberately as the prototype's does (dense catalogue grids, airy product sections, the tight R13 footer columns).
- **Project anti-patterns (from the prototype's locked visual rules):**
  - No page-specific chrome — header, drawers and footer come from the shell components; body-class scoping and the Home-only `.footer-cta` band are the only permitted variation.
  - No bold display headings — Charsen has one face at weight 400; never synthesise bold, never set a heading in the UI face.
  - No ivory page background — `#faf7f0` is history; pages are `#fff` (Home's opening section `#f2f1ee` and the `#faf9f6` washes are the only tinted surfaces).
  - No card shadows or hover lifts on art / collection / story cards — flat, border-only, hover = border colour.
  - No new animation registers — one easing, 200–300 ms, the Home handoff only; no parallax, autoplay, springs or cursor effects.
  - No guessed commercial copy or values — shipping charges, tax treatment, framed dimensions, cancellation/return/refund terms stay as the approved "pending" copy until the owner supplies them (D-PRE-13, OI-01–OI-05); no fake success states (D-PRE-20).
  - No dark mode, no mega-menu, no social links (D-PRE-12), no decorative search (D-11).
- **Admin anti-patterns (derived strictly from `prototype/admin/studio-ui.css` and the effective cascade):**
  - No storefront palette or fonts in the Admin — no crimson, gold, Charsen or Instrument Sans; no webfont at all (system stack only, `studio-ui.css:17`).
  - No serif anywhere except the "Aalishaan" sidebar word-mark (Georgia 29 px, `studio-ui.css:40`) — no Georgia headings, stat numbers, avatars or drawer titles.
  - No green primary button — primary actions are ink `#202923` (`studio-ui.css:80`); green `#264d3b` is an accent for current navigation, links, references, checkboxes and the current journey node.
  - No solid red button — danger is the soft `#fbefec` / `#a4473d` / `#efd5ce` treatment (`studio-ui.css:83`).
  - No filled dark current-nav item and no tinted sidebar — the sidebar is white and the current item is the pale `#edf5ef` tint with accent text (`studio-ui.css:39`, `:45`).
  - No loud borders — 1 px `#e7ebe7` hairlines only; no coloured left bars on notices (`studio-ui.css:171`); no dashed borders except the compact in-page placeholder (`:264`).
  - No card shadow heavier than `0 4px 20px #1b342907`, none on nested or embedded cards, and no hover lift or card transform anywhere (`studio-ui.css:15`, `:81`, `:169–170`).
  - No uppercase, letter-spaced table headers, section captions, stat labels or brand sub-label — sentence case throughout (`studio-ui.css:41`, `:111`, `:129`, `:230`); the record eyebrow is the one retained uppercase element.
  - No centred modal — every action opens in the right-side drawer (`studio-ui.css:249`); no second dialog pattern.
  - No underlined page-tab rows — in-page views use the segmented control, the product editor uses workspace tabs (`studio-ui.css:199–204`).
