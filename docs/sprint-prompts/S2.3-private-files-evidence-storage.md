Verified execution decisions, unresolved by preparation:

- **Delivery and expiry:** ROADMAP S2.3 requires signed URLs and also says no private object is reachable by URL alone. A signed URL is a bearer capability. Reconcile the literal acceptance rule before code: explicitly accepted short-lived bearer delivery with a proven cache/revocation bound, or per-request authorised delivery holding the Storage capability server-side, with the architectural adjustment recorded. Do not silently reinterpret the requirement. Current [Supabase signed-download documentation](https://supabase.com/docs/guides/storage/serving/downloads) describes shareable links; [Smart CDN documentation](https://supabase.com/docs/guides/storage/cdn/smart-cdn) says cached responses can outlive token expiry. Test warmed and cold cache paths. Staff logout/revocation or Auth-key rotation does not itself invalidate issued links; Storage uses [separate URL signing keys](https://supabase.com/docs/guides/storage/security/signing-keys). Retained original files must not be deleted to simulate revocation.
- **Permissions:** architecture §3c permits Owner/Operations to upload/download print originals and approval evidence; support is denied. Architecture §4 lists support as customer-evidence owner while §5 denies support every private file. Record metadata/list/upload/finalize/download/approval permissions by class and real parent, reconciling this conflict before enabling access. Finance exports remain owner-only. Unresolved classes default denied; neither Orders visibility nor a generic file ID grants authority.
- **Formats, limits and transport:** locked-facts §9a explicitly says prototype upload limits/formats are not production commitments. The prototype's 100 MB and broad archive/design-format list do not authorise a runtime whitelist. Select per-class byte/type/content rules and a feasible bounded transport. Current [Next Server Actions](https://nextjs.org/docs/app/api-reference/config/next-config-js/serverActions) default to 1 MB, [Vercel Functions](https://vercel.com/docs/functions/limitations) limit request/response payloads to 4.5 MB, and [Supabase Free upload limits](https://supabase.com/docs/guides/storage/uploads/file-limits) cap at 50 MB. Raising a framework limit alone does not solve hosting limits. Revalidate versions/plans at execution; any direct upload requires a narrow CSP/origin decision and private staging with server validation before readiness.
- **Lifecycle and future parents:** exact registry/state/constraint design and reserved `0007_files` numbering remain pending. Storage bytes and database rows are not one transaction. Define immutable completion, concurrent version allocation, idempotent recovery and scoped orphan retention. Current artworks/orders can anchor approved fixtures; jobs, inspections, claims and export producers are future dependencies. Deny unsupported parent types rather than accepting arbitrary entity IDs or inventing future tables. Approval owner/date stays unset until real authorised approval; upload is not approval.
- **Receipts, worker and backup:** preserve S1.8's distinct customer receipt capability and dedupe/private-object contract. A new reconciliation job is not implicit permission to extend S2.2's worker; name its exact kind/replay/pause/horizon design and scope first. S2.20 owns the restore drill; [Supabase database backups](https://supabase.com/docs/guides/platform/backups) do not contain Storage object bytes. Carry a bucket/version/retention/recovery handoff without claiming PITR alone protects originals.
