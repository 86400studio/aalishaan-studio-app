2. Make the smallest safe change inside the allowed file list.
3. Run the exact applicable commands and sprint-specific checks below.
4. Review the diff for scope, regressions, live env files, and secret exposure without printing values.
5. Commit or push only when the Git action policy below explicitly says YES.
6. Return the report below, then stop for the owner's next instruction.

Remote commands: proceed · pause · status · fix a named issue · skip to a numbered step.
A skip requires an owner-approved deferral to a named future sprint/backlog item. Do not mark the sprint
complete while an exit criterion remains unmet.

## Sprint-specific rules
- Verbatim copy: every visible string comes from the named prototype file or an NS row; a prototype
  string that describes a prototype mechanism (sample forms, previews, demo tracking) is not ported —
  it is replaced by its NS row or dropped, and the record says which.
- No fake success (D-PRE-20): the contact, newsletter and tracking forms render every control disabled
  (disabled attributes, not CSS) and never submit; no client script attaches a handler to them.
- No write anywhere: no server action, no route handler, no database or bucket call in src/; the only
  browser storage is the wishlist keys and the Cookies clear control.
- Tokens only: no inline hex in markup; new values become tokens recorded in DESIGN.md.
- Fonts never leave the public shell: no font import in the root layout or under src/app/admin.
- The Storage origin is the only CSP change; derived from NEXT_PUBLIC_SUPABASE_URL, never typed.
- The tool never names PROD, never prints a value, never reads a key outside the documented names.
