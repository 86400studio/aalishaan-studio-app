Verified gaps that must be resolved against the actual merged predecessors before execution:

- **Atomic worker/expiry primitives:** existing queue fields and uniqueness do not implement row-lock claims, leases/fencing, atomic completion/history or the shared expiry/finalization lock. Supabase JS makes separate PostgREST calls; locks cannot span them. `work_history` is append-only, requires attempt ≥ 1, allows only `succeeded/retry/dead/paused`, and lacks unique attempt accounting. The roadmap's additive `0004_messages` must explicitly cover the necessary supporting schema/functions or name separately approved migrations. Recheck numbering after S1.6/S1.7; never edit applied migrations or silently consume a reserved number. [PostgREST transactions](https://docs.postgrest.org/en/latest/references/transactions.html).
- **Email ambiguity:** D-06 remains an owner decision; Resend is a lean, not a configured account. Local dedupe cannot atomically commit provider acceptance. Resolve stable provider idempotency, frozen request inputs, lost-response recovery and the retry horizon. Resend currently retains keys for 24 hours; unbounded resend after that window is unsafe. Revalidate the chosen provider at execution. [Resend idempotency](https://resend.com/docs/dashboard/emails/idempotency-keys).
- **PDF storage/font:** architecture §7 requires private PDF storage and outbox retries, but only public catalogue storage exists. Define a minimal receipt-only private storage/access contract here, or obtain an explicit architecture/scope decision before changing that requirement; S2.3's broader private-file system does not exist yet. D-10's renderer choice/dependency and a licensed embeddable font with ₹ coverage require resolution. Existing Charsen OTF/Instrument Sans Latin WOFF2 files are not evidence of a usable, licensed PDF font; the website's Charsen acceptance does not grant PDF embedding rights. The renderer's current font support is TTF/WOFF. [React-pdf fonts](https://react-pdf.org/docs/v4/fonts).
- **SMTP and scheduling proof:** current staff auth has no mail callback/reset/invite completion flow. Select a bounded real Auth SMTP delivery/return test and any explicitly approved minimal route work; do not silently implement S2.1 or claim a correct-host 404 proves P3. D-16 requires Preview scheduling and an explicit test trigger. A new GitHub schedule runs from the default branch, so pre-merge route/dispatch proof and post-merge scheduled-run proof need separate dispositions. [GitHub schedule events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
