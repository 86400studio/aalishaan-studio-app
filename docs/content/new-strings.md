# docs/content/new-strings.md — Strings the Prototype Does Not Contain

The register for every customer- or staff-visible string the production build needs that has no verbatim source in the frozen prototype (`prototype/`): honest disabled-form notices, integration states, server errors, empty states for real data, email templates. Approved page copy is **not** duplicated here — `docs/APPROVED-INPUTS.md` §2 maps every page to its prototype source, and `docs/content/locked-facts.md` holds the exact claims.

Owner of this file: the sprint that first needs the string adds the row (D-08 lean, confirmed 2026-09-23 at S0.0). No sprint invents wording inline.

## 1. Rules

1. **No NS row reaches Production copy without owner approval** — except *honest technical states* (a form that is disabled, an order still being confirmed, an estimate not yet available, a synthetic-rule flag, an Admin section not built yet: NS-01–NS-06, NS-08, NS-09, NS-10, the NS-13 validation and resume-link states, NS-16), which may ship on the delivery lead's approval with owner review at the next check-in — decision D-24 in `PROJECT-STATUS.md` §8a (delivery-lead lean confirmed 2026-09-23 at S0.0; ~~owner confirmation requested~~ **confirmed by the owner 2026-10-19** — `PROJECT-STATUS.md` §5 #15; corrected 2026-10-29 at S1.4's step 0). Customer-facing commercial, policy or milestone wording (NS-07, any policy text) is always owner-approved (OI-09).
2. Every string follows the prototype's voice — short, plain, honest, no marketing claims, no "success" while data is discarded (D-PRE-20). Reference the closest prototype wording in the row so the voice can be checked.
3. A new string **never restates policy terms, prices, times, charges or dimensions the owner has not supplied** (D-PRE-13; `locked-facts.md` §11). "Pending" is stated as pending.
4. Wording is drafted **in the named sprint**, not here in advance. Until then the *Proposed wording* cell reads "wording to be drafted in the named sprint following the prototype's voice".
5. Status values: **Proposed** → **Owner-approved** (date + evidence link) or **Delivery-lead approved (technical state)** (date; rule 1) → **Superseded** (struck through, with the superseding NS row or decision ID). Never delete a row.
6. S3.1 clears this register: every remaining Proposed row is either owner-approved or replaced by the owner's supplied text (`docs/ROADMAP.md` S3.1 "`new-strings.md` cleared").
7. A string that turns out to exist in the prototype is not a new string — cite the prototype source and drop the row as Superseded. For Admin screens the prototype source is the final Admin (Admin A2 — 86400 UI edition, `prototype/admin/`, D-PRE-23) as it renders, that is after the allow-listed copy simplification in `prototype/admin/studio-ui.js`. Two things there are **not** approved sources: retained Admin A1 wording that still surfaces (for example "Return to Today" — `PROJECT-STATUS.md` §10 #8), and the labels of prototype-only mechanisms that are replaced, not ported (for example "Publish in demo", "Sign-out preview", "Download backup" — D-32); the production label for a replaced mechanism is a new string, added by the sprint that builds the replacement.
8. The E10 additions of 2026-09-23 put **draft** customer copy into the prototype (`prototype/shared/intake-e10.js`, `prototype/admin/e10-additions.js`, the checkout payment-policy line in `prototype/scripts/checkout-r9.cjs`, two FAQ entries and two policy sentences in `prototype/scripts/build-pending.cjs`). That copy is registered below as NS-12–NS-15 and is **not** approved page copy until the owner approves it (D-37, D-38); rule 7 does not apply to it. The staff-facing Admin labels the same additions introduce are NS-16 (rule 1).
