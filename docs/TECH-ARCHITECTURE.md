### Money

Every stored monetary value is an integer `bigint` in **paise** (`price_paise`, order totals, refunds, costs, settlement lines); no floats, no rupee columns anywhere in the database or server code (S1.1 risk note). Public pages display rupees formatted from paise: the locked launch prices are ₹19,000 / ₹21,000 / ₹23,000 = 1,900,000 / 2,100,000 / 2,300,000 paise for White / Black / Antique Gold (D-PRE-08; `prototype/data/pricing.json`). Currency is INR only. Shipping charges and tax treatment are owner inputs (OI-02, OI-03): until S3.1 they are versioned `business_rules` rows flagged `synthetic`, shown as "To be confirmed" exactly as the prototype does, never zero or a guessed value (D-PRE-13).

### Background work and idempotency

- **`pending_work` outbox** (S1.1): a business transaction that needs a follow-up (send confirmation, check readiness, issue document, release reservation, poll tracking, weekly digest) inserts a `pending_work` row **in the same transaction** as the state change. The worker (`GET /api/jobs/run`, `CRON_SECRET` as a Bearer token — D-16 as amended at S0.0) claims rows with row locks, retries with backoff within bounds, moves exhausted rows to dead-letter and records every attempt in `work_history`; per-type pause and an emergency pause are honoured (S2.2 failure queue — in the final Admin its home is Connections › "Automation & service health", which links "Incident & recovery details" and "Automation rules"; §3b).
- **`provider_events` ledger** (S1.1): every inbound Razorpay, Shiprocket and email-provider event is inserted first under a unique `(provider, event_id)`, then processed; a repeated, delayed or out-of-order event has exactly one business effect and never regresses a confirmed or delivered state (`SECURITY-CHECKLIST.md` §9 rule 4; S1.7, S2.10, S2.18).
- **Outbound idempotency**: Razorpay refund submissions are idempotent through our own refund row and the Razorpay `receipt` reference, with an "unknown → verify before retry" state via the Refunds API (S2.4; whether Razorpay offers an idempotency header is confirmed at that sprint's Gate 0, never assumed); Shiprocket shipment creation queries for an existing shipment before re-creating on timeout, one active intended shipment per parcel (S2.9).
- **Preview**: Vercel Cron does not fire on Preview deployments, so a GitHub Actions schedule (every 5 min) pings the stable Preview alias and Playwright triggers the worker explicitly in flow tests (D-16). Sandbox webhooks target a dedicated, serialised Preview alias using the Protection Bypass for Automation parameter (D-17; `ENVIRONMENT-PARITY.md` §7.11).
- **Pending-order expiry** (D-20): a pending order expires 60 minutes after its Razorpay Order is created; a captured payment arriving later sets `needs_review` and a readiness exception — never a silent refund or silent confirmation.

## 9. Security and deployment

- Security headers and transport controls are defined for the selected framework/host and verified on the deployed response: CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy on a catch-all rule at S0.1 (`curl -I` on Preview and Production shows all six); CSP extended for Razorpay origins at S1.6; re-verified whenever the diff touches them (`SECURITY-CHECKLIST.md` §6).
  - **As built at S0.1** (`src/lib/security-headers.ts`, applied by `next.config.ts` `headers()` with source `/(.*)` — `/:path*` does not match `/` in Next's strict matcher or Vercel's route conversion): `Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self'; font-src 'self'; connect-src 'self' <the https origin of NEXT_PUBLIC_SENTRY_DSN, when set>; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; upgrade-insecure-requests` (`'unsafe-eval'` is added to `script-src` for `next dev` only); `Strict-Transport-Security: max-age=63072000; includeSubDomains` (`preload` decided with D-04 at S3.4); `X-Frame-Options: DENY`; `X-Content-Type-Options: nosniff`; `Referrer-Policy: strict-origin-when-cross-origin`; `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=(), browsing-topics=()`. `X-Powered-By` is off.
  - **Recorded trade-off:** the App Router streams its React Server Components payload through inline scripts, so a static policy needs `script-src 'unsafe-inline'` (Next's own CSP guide; its experimental SRI does not hash these inline scripts).
